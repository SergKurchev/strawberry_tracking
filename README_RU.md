# Strawberry Tracker & Pose Estimator

Система для отслеживания клубники и восстановления позы камеры на основе глубокого обучения (YOLOv8) и извлечения признаков (DISK/LightGlue). Разработана для обработки синтетических данных из Isaac Sim и подготовки измерений для факторного графа GTSAM.

## Основные возможности и Архитектура (Dual-Pipeline)

Проект использует гибридный подход для решения конфликта между качественным трекингом мелких объектов и надежной визуальной одометрией:

1. **Фаза 1: Сфокусированный трекинг (Local Features)**
   - Нейросеть YOLOv8 детектирует ягоды.
   - Фон кадра маскируется (заливается черным), что заставляет экстрактор DISK генерировать ключевые точки *исключительно* на текстуре ягод.
   - **Результат:** Идеальная работа Венгерского алгоритма (Re-ID) без "воровства" признаков фоновыми объектами.
2. **Фаза 2: Глобальная локализация (Global Features)**
   - Параллельно DISK сканирует весь кадр целиком (ягоды, листья, стол, стены).
   - **Результат:** Богатая геометрия сцены исключает проблему "планарного вырождения" (Planar Degeneracy), позволяя алгоритму MAGSAC точно рассчитывать 3D-поворот и смещение камеры.
3. **Фаза 3: Долгосрочная память (Re-ID Gallery)**
   - Если ягода перекрывается листом и исчезает, её признаки сохраняются в `gallery` на заданное количество кадров.
   - При повторном появлении трекер сопоставляет её с галереей и восстанавливает исходный ID.
4. **Устойчивость к паузам (Small Motion Fallback)**
   - Если среднее смещение точек между кадрами меньше `min_motion_thresh` (например, 1.0 пиксель), система фиксирует остановку камеры и возвращает единичную матрицу поворота, защищая алгоритм от математического взрыва.

## Математика и Параметры камеры

Для точной локализации алгоритм использует законы эпиполярной геометрии.

### 1. Матрица внутренних параметров ($K$)
Физические параметры камеры из Isaac Sim (миллиметры) конвертируются в пиксельные значения для OpenCV:

$$f_{px} = f_{mm} \cdot \frac{W_{px}}{A_{horiz}}$$

При разрешении $1920 \times 1080$, фокусном расстоянии $18.0$ мм и горизонтальной апертуре $20.955$ мм, матрица интринсиков $K$ выглядит так:

$$K = \begin{bmatrix} 1649.25 & 0 & 960.0 \\ 0 & 1649.27 & 540.0 \\ 0 & 0 & 1 \end{bmatrix}$$

### 2. Расчет Одометрии (Essential Matrix)
По глобальным совпадениям ключевых точек вычисляется Существенная матрица (Essential Matrix) $E$, удовлетворяющая условию:
$$x_2^T E x_1 = 0$$
где $x_1, x_2$ — нормализованные координаты сматченных точек на смежных кадрах. 
Для очистки от шума применяется робастный алгоритм оптимизации (по умолчанию `MAGSAC`). Матрица $E$ затем декомпозируется в итоговые:
- **$R$**: Матрица поворота ($3 \times 3$).
- **$t$**: Вектор смещения ($3 \times 1$, нормализованный).

## Использование (API трекера)

Пример интеграции трекера `StrawberryTracker` в ваш пайплайн с поддержкой Dual-Pipeline:

```python
import yaml
import torch
import numpy as np
from ultralytics import YOLO
from strawberry_tracker import StrawberryTracker

# 1. Загрузка конфигурации
with open('config.yaml', 'r') as f:
    config = yaml.safe_load(f)

# 2. Инициализация моделей
yolo = YOLO(config['yolo_weights_path'])
tracker = StrawberryTracker(yolo, device='cuda', config=config)

# 3. Интринсики камеры (1920x1080, Isaac Sim)
K = np.array([
    [1649.25, 0, 960.0],
    [0, 1649.27, 540.0],
    [0, 0, 1]
], dtype=np.float32)

# 4. Обработка кадра (Формат должен быть RGB!)
img_rgb = ... # Загрузка кадра
R, t, ids, boxes, matches1, matches2, inliers1, inliers2, debug = tracker.forward(img_rgb, K)
```

**Формат выходных данных `forward`:**
- `R`, `t`: Относительный поворот и смещение камеры.
- `ids`: Массив глобальных ID ягод (например, `[0, 4, 12]`).
- `boxes`: Bounding boxes `[x1, y1, x2, y2]`.
- `matches1`, `matches2`: Все найденные совпадения ключевых точек (сырые данные).
- `inliers1`, `inliers2`: Координаты точек сцены, прошедших фильтрацию MAGSAC (идеально для визуализации одометрии).

## Экспорт данных (GTSAM Integration)

В файле `config.yaml` доступен режим `export_data: true`. При его включении скрипт `test_on_coco.py` автоматически агрегирует всю информацию о сцене и сохраняет её в директорию `exported_data/`:

1. **`poses.csv`**: Матрицы поворота ($R$) и векторы ($t$) построчно (фрейм, r11-r33, tx, ty, tz).
2. **`tracking.json`**: ID ягод и координаты их боксов (для метрик MOTA/IDF1 и точечных факторов в GTSAM).
3. **`inliers.json`**: Точные координаты пар точек, прошедших RANSAC (готовые landmarks для Loop Closures).

### Пример загрузки и анализа данных (Python / Pandas)

```python
import json
import pandas as pd
import numpy as np

# 1. Загрузка траектории камеры (Одометрия)
poses_df = pd.read_csv('exported_data/poses.csv')
print("Первые 5 кадров одометрии:")
print(poses_df.head())

# Восстановление матрицы вращения R (3x3) для нулевого кадра
row = poses_df.iloc[0]
R = np.array([
    [row['r11'], row['r12'], row['r13']],
    [row['r21'], row['r22'], row['r23']],
    [row['r31'], row['r32'], row['r33']]
])

# 2. Загрузка трекинга ягод
with open('exported_data/tracking.json', 'r') as f:
    tracking = json.load(f)

# Практический пример: сбор траектории одной ягоды (ID 0)
berry_0_trajectory = []
for frame_name, detections in tracking.items():
    for det in detections:
        if det['id'] == 0:
            # Вычисление центра Bounding Box
            bbox = det['bbox']
            center_x = (bbox[0] + bbox[2]) / 2
            center_y = (bbox[1] + bbox[3]) / 2
            berry_0_trajectory.append((frame_name, center_x, center_y))
            
print(f"\nЯгода ID 0 успешно отслежена на {len(berry_0_trajectory)} кадрах.")
```
